🆕 What's new in 2026

The four shifts worth knowing

The field moved fast over the last year. Here's what actually changes how we work — beyond the hype.

🤖

AI agents, not just chatbots

Modern AI doesn't only answer — it acts. Tools like Claude Code, GitHub Copilot Agent mode and Cursor can read your files, run commands, edit documents and update Jira on their own, then report back. You go from "ask & copy-paste" to "delegate & review".

🧠

Reasoning ("thinking") models

The latest models (Claude Opus 4.8, the GPT-5 family, Gemini) can think before answering on hard problems — planning, multi-step logic, trade-off analysis. Slower, but dramatically better on complex specs, risk analysis and edge cases.

📚

Huge context windows

Models now read up to ~1M tokens at once — that's hundreds of pages. You can paste an entire PRD, a full transcript, or a whole spec folder and ask questions across all of it. No more chopping documents into pieces.

🔌

The MCP ecosystem exploded

The Model Context Protocol became the standard way to connect AI to your tools. Jira, Confluence, Figma, GitHub, Slack, Notion, Google Drive… one protocol, dozens of integrations, all usable straight from your editor's chat.

🔥 Tips & Tricks

The tricks that change everything

Concrete techniques tested by thousands of users — from the simplest to the most advanced.

🦴 Classic

Caveman prompting

No need for elaborate sentences. AI understands direct, minimal commands very well. Short = often better. Like a caveman: straight to the point.

❌ "Could you please, if you wouldn't mind, write me a summary of this meeting in a structured format..." ✅ "Summarize. 5 bullets. Pro tone. Max 80 words."
🇬🇧 $$$ Tip

Prompting in English = better + cheaper

LLMs are trained mostly on English. Prompting in English improves answer quality and uses fewer tokens. Fewer tokens = cheaper for the company. You can still ask for the final answer in French.

FR prompt → correct answer, more tokens ✅ EN prompt + "Answer in French" → better quality, ~20-30% fewer tokens
🎭 Role Prompting

Give the AI a precise role

AI performs far better when you assign it a specific expertise up front. It's the simplest and most impactful technique there is.

❌ "Write a user story about login" ✅ "You are a senior PM at a French mortgage platform. Write a user story for..."
🔢 Structure

Number your constraints

For complex requests, list your constraints as numbers. AI follows an ordered list far better than a dense paragraph.

1. Answer in French
2. Jira table format
3. Max 5 lines
4. Direct tone, no pleasantries
🪞 Chain of Thought

"Think step by step"

Adding this phrase drastically improves quality on complex topics. AI reasons better when it externalizes its thinking before concluding.

✅ "Think step by step. What are the main risks of removing the confirmation screen in our mortgage funnel?"
📌 Few-Shot

Give examples (few-shot)

Showing 1 or 2 examples of the expected result is often more effective than 10 lines of explanation. AI mimics the format with remarkable precision.

❌ "Write a short, actionable ticket title" ✅ "Write a ticket title like: 'Add CTA on summary page', 'Fix email on step 3'. Now write one for: [desc]"
♻️ Workflow

Iterate, don't restart

Don't open a new conversation when the result isn't perfect. Refine in the same thread: the AI keeps the context and each iteration is instant.

"Shorten the title"
"Make the 2nd criterion more precise"
"Add an error case"
"Now translate to English"
⚠️ Caution

Be skeptical of numbers & dates

LLMs invent statistics with absolute confidence. Never use a generated figure without sourcing it. AI is excellent for structure — you provide the real numbers.

❌ "43% of customers drop off at step 2" ← made up ✅ Ask it for the structure, then inject your real data
🎲 Creativity

Ask for several variants

Instead of accepting the first proposal, systematically ask for variants. The best choice is often variant B or C. It takes 2 extra seconds.

✅ "Give me 3 versions of this title: formal / neutral / punchy"
🧩 Advanced structure

The 3-block prompt

The most effective structure for complex tasks: Context + Task + Constraints.

[Context] PM on MeilleurTaux credit team, mortgage funnel
[Task] Write acceptance criteria for 2FA feature
[Constraints] Gherkin format, 5 scenarios max, answer in English
🚀 VS Code

The "/" commands in Copilot

In Copilot Chat, typing / shows quick commands. Perfect for getting straight to the point without writing a full prompt.

/explain → understand a file or code
/doc → generate documentation
/fix → fix an error
/tests → generate tests
🎯 Mindset

AI as a brilliant intern

Imagine briefing a very smart intern with no business context. The more precise your brief, the more relevant the result. A mediocre output almost always comes from an insufficient brief.

Vague brief → generic, unusable output
Precise brief + business context → directly usable output
🧠 New · 2026

Pick the right mode: fast vs thinking

For quick rewrites or summaries, the fast model is enough. For hard problems — risk analysis, multi-step specs, edge cases — switch to a reasoning/thinking model and let it plan. Don't burn a thinking model on "shorten this title".

Quick task → fast model, instant answer ✅ "Think hard about the edge cases of this refund flow" → reasoning model
📚 New · 2026

Paste the whole document

Context windows are now huge (~1M tokens). Stop summarizing inputs by hand — paste the full transcript, PRD or spec folder and let the AI work across everything. More raw context almost always beats a hand-trimmed snippet.

✅ "Here's the full 40-page discovery transcript. Extract the top 5 pain points with verbatim quotes."
🤖 New · 2026

Let the AI act, not just answer

In agent mode (Copilot Agent, Claude Code, Cursor), the AI can take real actions: edit files, run scripts, update Jira via MCP. Give it a goal and let it work in a loop — then review the diff before validating.

✅ "Read this PRD, draft the user stories as a checklist, then create them in Jira project MTX. Show me before saving."
🛡️ New · 2026

Always review the diff

Agents are powerful but not infallible. Before accepting an action — a ticket batch, a file edit, a status change — read what it actually did. Treat the AI like a fast junior whose work you sign off on, never a black box.

Agent proposes → you read the diff → you approve or correct → only then it commits
✅ Best practices

The golden rules

What to do, what to avoid, and how to write an effective prompt.

✅

Do

  • Always review and validate outputs
  • Give precise context in your prompts
  • Iterate: refine over several exchanges
  • Specify the expected format (bullets, table…)
  • Use AI for a first draft, not a final output
  • Try several phrasings if the result disappoints
  • Share good prompts with the credit team
  • Use tools approved by IT/Security
⛔

Don't

  • Share customer or confidential data
  • Copy-paste without checking (hallucinations!)
  • Use unapproved tools on internal data
  • Treat AI as an absolute source of truth
  • Trust numbers without verifying them
  • Publish an AI output without reviewing it
  • Use public ChatGPT for sensitive content
  • Forget that AI can carry biases
⚠️

Data security: Never enter personal customer data, credentials, contracts or financial information into unapproved AI tools. When in doubt, contact IT/Security (DSI).

🎯 Concrete example: bad vs good prompt

Bad prompt

Make me a Jira ticket for the login feature.

❌ Too vague
Good prompt (in English for better results)

You are a senior PM at MeilleurTaux, a French mortgage comparison platform.
Write a Jira ticket in French for this user story:
"As a logged-in user, I want to receive an email when my file moves to 'En cours d'instruction'."
Format: short title, description with context, acceptance criteria (bullet list), definition of done.

✓ Precise + EN
💻 Tools

VS Code & GitHub Copilot

Even if you're not a developer, VS Code + Copilot is the most powerful environment for working with AI.

💡

Why VS Code for PMs? VS Code is no longer just for devs. With GitHub Copilot, it's an ultra-powerful AI environment for writing specs, analyzing files, and connecting your tools (Jira, Confluence, Figma) via MCPs.

🆕

Not into VS Code? Two great alternatives in 2026: Cursor (an AI-first editor, very beginner-friendly) and Claude Code (a terminal agent that reads your files and acts). Both speak MCP too. Pick whatever you'll actually open every day — the techniques on this page apply to all three.

📦 Step-by-step installation

1

Download VS Code

Go to code.visualstudio.com → macOS build (Apple Silicon if you have a recent Mac) → drag it into Applications.

2

Install the GitHub Copilot extension

Extensions ⌘⇧X → search GitHub Copilot → Install. Also install GitHub Copilot Chat for the conversational mode.

3

Sign in with your GitHub account

Click the account icon at the bottom → "Sign in with GitHub" → authorize in the browser. Your Copilot license must be active (see the Access section).

4

Open Copilot Chat

Shortcut ⌃⌘I or the Copilot icon in the sidebar. The chat panel opens — talk to it with the context of all your open files.

5

Enable MCPs (Jira, Confluence, Figma…)

MCPs connect Copilot to your tools. See the MCP section below for step-by-step Jira configuration.

🔌 MCP

What you can do with MCP Jira

The Model Context Protocol connects GitHub Copilot directly to Jira. No more copy-pasting between tabs!

🧩

What is an MCP? A bridge between your AI and your tools (Jira, Confluence, Figma, GitHub…). Once configured in VS Code, you can ask Copilot to read, create and update Jira tickets right from the chat.

⚡ Available actions with MCP Jira

Action What you tell Copilot Result Level
Create a ticket "Create a ticket in project X for this user story: [desc]" Ticket created with title, description, type, priority ✓ Simple
Read tickets "Show the open tickets in project Y's current sprint" List with statuses, assignees, priorities ✓ Simple
Update "Change MTX-1234 status to 'In progress', assign to Marie" Ticket updated in real time in Jira ✓ Simple
Comment "Add a comment on MTX-567: 'Front POC validated, waiting on back'" Comment posted in Jira ✓ Simple
Search "Find all High bugs linked to the credit subscription funnel" Filtered, readable JQL results ✓ Simple
Batch create "From this PRD, generate the user stories and create them in Jira" Automatic creation of multiple tickets ⚡ Advanced
Summarize an epic "Summarize the progress of epic MTX-100 with its sub-tasks" Narrative synthesis of scope and progress ⚡ Advanced
Link tickets "Create a 'blocks' link between MTX-200 and MTX-201" Dependency created between the two tickets ✓ Simple

⚙️ Configuring MCP Jira in VS Code

1

Generate a Jira API token

Go to id.atlassian.com/manage-profile/security/api-tokens → Create token → Copy it (shown only once).

2

Open VS Code settings

⌘⇧P → "Open User Settings (JSON)" → add the MCP configuration in the mcp.servers section.

3

Configure the Atlassian MCP server

Fill in ATLASSIAN_EMAIL, ATLASSIAN_TOKEN and the instance URL: meilleurtaux.atlassian.net.

4

Test the connection

In Copilot Chat, type: "List the available Jira projects". If it works, Copilot lists your projects within seconds. 🎉
